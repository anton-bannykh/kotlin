# SpecialInteropIntrinsicsLowering

Replaces the cinterop intrinsic `typeOf<T>()` (the one in `kotlinx.cinterop`, not `kotlin.reflect.typeOf`) with the companion
object of `T`. That companion holds the size and alignment of the C type.

**Why:** `sizeOf<T>()`, `alignOf<T>()` and `alloc<T>()` are inline functions with a reified `T`, all built on `typeOf<T>()`.
Which class `T` is becomes known only after they are inlined into the caller, so this cannot be done earlier.

```kotlin
// in kotlinx.cinterop
class IntVarOf<T : Int>(rawPtr: NativePtr) : CPrimitiveVar(rawPtr) {
    companion object : Type(4)                  // size 4, alignment 4
}
inline fun <reified T : CVariable> sizeOf(): Long = typeOf<T>().size

// before (sizeOf is already inlined)
fun size(): Long = typeOf<IntVarOf<Int>>().size
fun make(scope: MemScope) = scope.alloc(size = typeOf<IntVarOf<Int>>().size, align = typeOf<IntVarOf<Int>>().align)

// after
fun size(): Long = IntVarOf.Companion.size
fun make(scope: MemScope) = scope.alloc(size = IntVarOf.Companion.size, align = IntVarOf.Companion.align)
```

**Know this**
- Every class that describes a C variable (`IntVar`, a struct generated by cinterop, …) must have such a companion.
  If it has none, compilation fails here.
- A `typeOf<T>()` whose `T` is still a type parameter is left alone. That only happens in the leftover body of the inline
  function itself.
